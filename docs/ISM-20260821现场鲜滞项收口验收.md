## 1. 历史库前端备份（taosdump）— **本 PR 新改**

### 根因（8/20 现场）

`taosdump -p <password>` 把密码拆成独立参数 → TDengine 进入交互输密，把 `taosdata` 当成库名，再叠 `-A` 全库冲突，并报 `ioctl`。

### 本 PR 改动

文件：`ism_server_user/controllers/hisDbOpt.go`

| 项 | 修复前 | 修复后 |
|----|--------|--------|
| 密码 | `-p`, `pass` 两个参数 | `-p` 紧贴密码，如 `-ptaosdata` |
| 库范围 | `-A` 全库 | `-D ISMHistoryDb` 仅业务历史库 |
| Docker | `docker exec -i` | `docker exec -T`（非交互，避免 ioctl） |
| 容器内连接 | 用 REST 6041 | 容器内改连 `127.0.0.1:6030` |

### 现场复验

- [ ] 历史库配置页（TDengine，`historyrecorddbtype=2`）点击「备份 TDengine 历史库」
- [ ] 返回 `code: 0`，`data/hisdbbackup/ISM_TDengine_Backup_*` 目录有文件
- [ ] `ism.log` 出现类似：`HisDbBackUp docker taosdump: docker exec -T tdengine taosdump -h 127.0.0.1 -P 6030 -u root -p*** -D ISMHistoryDb -o /tmp/...`
- [ ] **不再出现**：`taosdata is an invalid input if database(s) be already specified`
- [ ] **不再出现**：`Cannot get the attribution of the terminal: Inappropriate ioctl for device`

## 5. 定时入库 2208 点 / 600s — **8/19 已在 main，本 PR 未改管道**

快照任务：`task/historydata/timedRealtimeHistorySnapshot.go`（独立 1s ticker，不走采集入队主路径）。

### 日志字段（已足够区分，无需再加）

每分钟（有写入或无实时值时）汇总一行：

```text
timed history snapshot tick: wrote=%d fromDB=%d reusedLast=%d noRealtimeValue=%d notDue=%d points=%d
```

| 字段 | 含义 |
|------|------|
| `wrote` | 本秒实际入队写入档数 |
| `fromDB` | 内存无值、从 `device_real_data` 补读成功 |
| `reusedLast` | 无实时值，复用上一档 |
| `noRealtimeValue` | 既无实时值也无上一档，本周期跳过 |
| `notDue` | 未到定时刻度 |

**判定**：`noRealtimeValue` 高 → 采集/实时库缺值；`wrote` 长期为 0 且 `noRealtimeValue` 低 → 查 TDengine 写入/async 缓冲（见 `dealWithHistoryData.go` Error 日志），**不是**本 tick 字段混淆。

### 现场复验（≥1 小时 ism.log）

- [ ] 启动后有 `timed history snapshot points loaded: 2208`（或现场实际定时点数）
- [ ] 600s 间隔点位：1 小时约 **6 条** 历史记录/点（允许 ±1）
- [ ] 1 小时内多次出现 `timed history snapshot tick`，且 `wrote+fromDB+reusedLast` 与缺档情况可对应解释
- [ ] **不再**按点刷屏 `no realtime value yet, skip cycle`
