# AI 日常办公实战：先学会用 WorkBuddy

> **对象**：寻智元盛（循安科技软件研发 / AI 部门）及相关同事  
> **组织背景**：循安科技与寻联盛同属一个集团；寻智元盛≈循安侧软件研发 / AI 部门  
> **时长**：约 60–75 分钟（2026-10-26 周一上午，具体时刻另定）  
> **形式**：讲解 + 口述演示脚本 + 现场提问

## 开场（3 分钟）

### 今天不讲什么

- 不讲「AI 会不会取代人类」的空讨论  
- 不讲模型参数、论文细节  
- 不承诺「立刻上线一套企业级大系统」或「全员已开通所有能力」  
- 不声称 EMS 已全量交付、已过等保、或已承接开票报税

### 今天要讲什么

1. **先学会用 WorkBuddy**：腾讯 AI Agent 办公工作台——自然语言下任务、拆解执行、交文档 / 表 / PPT；工作用途清单；怎么下指令；**专家与技能怎么直接用**  
2. **Grok Bot（压缩）**：主助手 + 专项助手；电脑 + 手机；跟 WorkBuddy 怎么配合  
3. **微信联动（压缩）**：手机发令 → 电脑执行（目标形态 + 现在能演示到哪）  
4. **EMS**：逐渐把工作管起来——合同 / 台账索引 / 软著资质 / 审批等；AI 起草，人确认后进系统

**一句话定调**：今天先学会用 WorkBuddy；AI 是「副驾驶」，方向盘还在你手里——回去就能少干一件重复活。

## 一、WorkBuddy 上手（主战场，25–30 分钟）

> 口语「沃克巴」= **WorkBuddy（腾讯）**。本场统一用 WorkBuddy。

### 1.1 是什么

**WorkBuddy（腾讯）**：全场景 AI Agent 办公工作台。

- 你用**自然语言**描述需求（一句话也能下任务）  
- 它会**自主规划、拆解步骤、调用工具执行**  
- 交付可验收结果：文档、表格、PPT、分析结论等（可直接拿去改）  
- 定位：从「聊天问答」升级为「像同事一样把活干完」的桌面工作台  
- 与腾讯办公生态有连接能力（讲到「生态」即可，勿展开未核实的具体开通清单）

> 现场说法：「它不是多一个聊天窗口，是多一个能拆任务、交成果的办公搭子。」

### 1.2 工作用途清单（可投屏）

> 原「日常办公场景地图」并入本表，避免重复。原则：输入 → AI 做什么 → 你验收什么。

| 场景 | 你给什么 | WorkBuddy 帮你什么 | 你过一眼 |
|------|----------|-------------------|----------|
| 邮件 / 通知 | 要点、语气要求 | 正式稿 / 简洁稿 | 口径、署名、收件人 |
| 会议纪要 | 粗糙笔记或转写 | 决议、Owner、截止日期 | Owner 是否对、有无漏项 |
| 周报 / 月报 | 任务列表 + 卡点 | 进展 / 风险 / 下周（下月）计划 | 删不准的、补敏感口径 |
| 报销 / 填表 | 票据信息（脱敏） | 科目建议、事由草稿、缺项清单 | 制度、真伪、最终提交 |
| 查资料 · 对比 | 问题 + 已有材料范围 | 摘要、对比表、待核实清单 | 出处、是否过时 |
| 做表 / 做 PPT | 大纲或原始数据 | 表格结构、幻灯骨架、讲稿要点 | 数字、结论、品牌口径 |
| 研发小助手 | 报错 / 片段 / 需求（点到为止） | 解释、方案草稿、测试清单 | Code Review，责任在人 |

**金句（可投屏）**：

> 办公 AI 的价值，不是「替你点提交」，是「第一次就填对的概率变高、被退回的次数变少」。

研发只点到为止：读懂陌生模块、小 bug 方案草稿、用例清单——能用，但今天主战场是**全员办公**；上线决策与最终责任永远在人。

### 1.3 怎么用（步骤）

1. **打开** WorkBuddy（账号开通听部门 / IT 安排，本场不替采购拍板）  
2. **开对话**：普通对话即可开工；需要专业视角时再召唤专家（见下节）  
3. **指令四件套**（口头重复两遍）：  
   - **目标**：要交什么（一份 PPT / 一张表 / 一封邮件）  
   - **材料**：给你看哪些文件、表格、笔记（或说明没有）  
   - **约束**：篇幅、语气、格式、不要改什么  
   - **验收标准**：怎样算完成（例如「3 页以内、有风险栏、有 Owner」）  
4. **验收草稿**：默认当草稿——先扫数字 / 人名 / 日期 / 承诺语气，再删幻觉、补业务口径  
5. **人点发送 / 提交**——责任在人

**差指令**：「帮我弄一下周报。」  
**好指令**：「根据下面任务列表，写本周周报：进展 / 风险 / 下周计划各三条以内；风险要写影响；不要编造没有的完成项。」

### 1.4 专家与技能（可直接用）

#### 入口

左侧边栏 → **「专家」** / **「专家·技能·连接器」**（专家页签、技能页签）。

#### 三分法（官方对比口径）

| | Skill（技能） | 专家 | 专家团 |
|--|---------------|------|--------|
| 是什么 | 工具能力：让 AI 能做某件事 | 能力 + 经验：懂某个领域的 AI 角色 | 多专家协作：团长拆解、并行执行、整合交付 |
| 怎么选 | 需要某种工具能力（读表、出 PDF、连腾讯文档…） | 有一个明确的单点专业问题 | 任务复杂，需要多角色配合 |

**口诀**：Skill 是手；专家是脑+手；专家团是一支小队。

#### 专家常见大类（可直接召唤；按行业分类浏览）

广场约 **100–150+** 位领域专家、持续更新——**勿写死未核实的具体专家昵称**（除非注明「示例」）。讲大类即可：

| 大类 | 典型用途（示例方向） |
|------|----------------------|
| 研发工程 | 前端 / 后端 / 架构 / DevOps：读代码、方案草稿、自动化脚本（点到为止） |
| 产品设计 | PM / UI：需求整理、原型说明、交互要点 |
| 数据分析 | 表格清洗、指标汇总、可视化说明 |
| 市场运营 / 文案 | 文案、内容策划、对外说明草稿 |
| 效率工具 / 文档 | 文档整理、PPT 骨架、纪要与清单 |

召唤步骤：专家中心浏览 / 搜索 → **召唤专家** → 用自然语言描述任务。复杂活可试**专家团**（积分通常高于单专家，以现场提示为准）。

#### Skill：优先官方 SkillHub

- 办公向常见方向：腾讯文档连接、Word / Excel / PDF / PPT 处理类、本地文件整理类（以技能市场当前上架为准）  
- **安装方式**：  
  1. 技能页 → 点卡片 **+** 安装；或  
  2. 对话里说「帮我找一个能……的技能」→ 确认后安装  
- **安全**：优先官方 / 官方推荐；第三方慎装（看清来源、权限、脚本）；**敏感客户数据 / 密钥勿丢进未授权 Skill**

### 1.5 口述演示脚本（现场选 1–2 个；时间紧砍演示 3）

**演示 1｜会议笔记 → 行动项表**

1. 口述或贴一段脱敏会议笔记  
2. 指令：「整理成表格：决议 / Owner / 截止日期 / 待确认；待确认单独一列。」  
3. 指着结果说：Owner 对不对、日期是否空、有没有把闲聊写成决议——人改完再发群

**演示 2｜零散要点 → 周报**

1. 丢 5–8 条本周杂记  
2. 指令：「按进展 / 风险 / 下周计划输出；每条不超过一行；没有的进展不要编。」  
3. 强调：AI 爱「补全」，你要删掉编出来的完成项

**演示 3｜大纲 → PPT 骨架（可选，时间紧可砍）**

1. 给标题 + 3 个论点  
2. 指令：「生成 6 页以内幻灯大纲：每页标题 + 3 条要点 + 建议配图说明；结论页要有下一步。」  
3. 人补：真实数据、客户名口径、品牌色

可选加一句：「需要专业视角时，先在专家中心召唤对应大类专家，再下同样四件套指令。」

**演示话术收口**：「WorkBuddy 的价值是把『从零空想』变成『审稿交货』——你从打字员变成主编。」

### 1.6 适合 / 不适合 + 边界

| 更适合 | 不适合 / 需谨慎 |
|--------|-----------------|
| 多步办公任务：读材料 → 整理 → 出表 / 出稿 / 出幻灯 | 需要你本人签字、对客户承诺的最终决策 |
| 结构清晰的交付物：周报、清单、对比表、方案骨架 | 把未脱敏客户全量数据直接丢进去 |
| 「帮我做完这件事」而不是「随便聊两句」 | 期望「一次就对、不用验收」 |

- 账号开通、公司统一选型、内网策略：以行政 / IT / 部门安排为准  
- 个人试用也要守红线（见红线节）  
- 勿承诺具体价格、套餐名、未核实的「已全员开通」

## 二、Grok Bot（约 8–10 分钟）

> 口语里同事可能说「五克巴蒂」——指的就是 **Grok Bot**。本场统一用 Grok Bot。

### 2.1 一张分工图

```
你（指挥官）
  ├─ 主助手：日常问答、统筹、跨任务协调
  ├─ 专项助手 / 项目组助理：盯某一类活（如某项目、某类文档、某条业务线）
  ├─ 电脑端：适合长任务、多文件、持续跟进
  └─ 手机端：路上补一句、催进度、看结果、快速拍板口径
```

### 2.2 电脑端 vs 手机端（压缩讲）

| | 电脑端 | 手机端 |
|--|--------|--------|
| 适合 | 改文件、长文、多步任务、对着大屏验收 | 移动中下指令、催办、看结论、快速确认 |
| 注意 | 长任务要盯验收 | 别在手机上贴密钥 / 全量客户表 |

### 2.3 和 WorkBuddy 怎么配合

- **WorkBuddy**：偏「办公工作台 / Agent 交货」——文档、表格、PPT；可召唤专家 / Skill  
- **Grok Bot**：偏「你的助手体系」——可持续对话、分助手盯项目、电脑 + 手机一体指挥  
- 不是二选一：常见用法是「WorkBuddy 交货、Grok Bot 跟项目 / 跟催 / 跨工具协调」  
- 具体账号谁开通：按部门安排，本场给方法不绑死工具唯一论

**30 秒例子**：「早上在电脑上让专项助理整理项目风险清单；中午手机上看一眼结论；下午在 WorkBuddy 里把清单收成一页进展表——人只做验收和口径。」

## 三、微信指挥机器人 + 手机电脑联动（约 5–6 分钟）

### 3.1 目标形态

```
微信里发一句指令
    → 机器人接收 / 桥接
    → 电脑侧助手执行（查、写、整理、催办）
    → 结果回微信或回电脑端给你验收
```

价值一句话：**人在手机上指挥，重活在电脑上干，两边不断档。**

### 3.2 当前可演示路径（诚实口径）

请按现场真实情况勾选讲述，**禁止说成「全员已经默认开通」**：

1. **已能演示（若现场环境具备）**：微信对话机器人接收指令 → 触发已连接的电脑侧任务 → 回传简要结果或状态  
2. **部分同学可试用**：需单独开通 / 绑定；不是人人一点即有  
3. **建设中 / 按项目推进**：联动范围、权限、审计还在收紧——先小范围验证再铺开

现场推荐说法：

> 「这是我们要的工作方式：微信当遥控器，电脑当工位。今天能演示到哪一步，以现场账号为准；没开通的同事先记住形态，本周用 WorkBuddy 也能先练下指令习惯。」

### 3.3 好用的微信指令

短、可执行、可验收：

- 「把今天站会笔记整理成三条行动项，Owner 先空着。」  
- 「催一下 XX 项目助理：风险清单进度。」

避免：「帮我弄一下那个。」；直接转发未脱敏合同 / 密码 / 全量点位表。

## 四、EMS：把工作逐渐管起来（约 8–10 分钟）

### 4.1 桥接故事（从 AI 工具到「公司一本账」）

WorkBuddy / Grok Bot / 微信联动，解决的是**个人与小团队怎么更快干活**。  
下一步是：把散落在网盘、表格、微信群里的关键信息，逐渐收进 **EMS（企业管理系统）**——让合同、台账索引、软著资质、审批等有一个可检索、可归档的入口。

> 现场说法：「AI 帮你起草和催办；人确认之后，进 EMS——工作才真正被管起来。」

**诚实边界（必须口头强调）**：

- 今天讲的是方向与已能看见的能力，**不是「已经全量上线、全公司都在用」**  
- **不要说**：已过等保、已替代开票报税、项目/采购/交付业务已完整交付  
- 项目模块目前主要是占位；采购 / 交付业务写能力尚未就绪——可作「最先做」目标提一句，**禁止讲成已上线**

### 4.2 EMS 能帮什么（可讲的范围）

按「AI 起草 → 人确认 → 进 EMS」来讲：

| 方向 | 同事日常怎么用 | 注意 |
|------|----------------|------|
| 相对方 / 合同 | 登记合同、挂附件索引、查状态与到期 | 金额等关键变更要有人确认，不静默改 |
| 财务台账索引 | 流水与发票等凭证**索引**（指向网盘等），方便对账检索 | **不是**核算引擎，也**不替代**开票报税 |
| 软著 / 资质 | 进度、材料索引、证书台账 | 正式递交仍走版权中心路径，系统不管「点提交」 |
| 文档索引 | 标题、类型、路径、关联对象 | **不搬文件本体**，不替换现有网盘 |
| 审批中心（方向） | 待办、审批入口，把确认动作留痕 | 讲「方向 / 已有能力边界」，勿夸成全公司流程引擎已就绪 |

**一句话分工**：AI 出草稿与催办；人过目、拍板；EMS 留底、可查、可审计。

### 4.3 智能化怎么接进来（目标形态，勿称已全员交付）

三条都能走，看公司先推哪条：

1. **WorkBuddy**：日常交流互动、随手交货（文档/表/PPT）  
2. **Grok Bot 挂 EMS**：助手侧提供「打开 / 看到 EMS 界面」的入口，用助手做查、填草稿、催办，人过一眼再落库  
3. **EMS 内嵌智能体**：人就在 EMS 页面里问、填、催——系统内直接智能化  

**接法（技术一句话）**：EMS 先暴露 **API** → 经 **MCP**（或同类工具门禁）接到助手；智能体**只调工具门禁，不直写库**。

> 现场说法：「交流互动靠 WorkBuddy；管起来靠 EMS；智能体可以挂在外面指挥，也可以长在 EMS 里——中间用 API + MCP 接好。」

### 4.4 部署怎么选（给「公司要不要弄一台」的诚实答案）

若只是**内网演示 / 本机试用**：办公室机器或笔记本本地起 demo **可以**，同事连同一内网即可。  

若要让**公司相关同事从外网也能稳定访问**（云帆已提：固定 IP、外网能访问）：

1. **需要**：固定公网 IP（或域名解析到该 IP）+ **HTTPS**（证书）  
2. **更省心的优先选项**：**阿里云 ECS + 弹性公网 IP（EIP）**——公网入口稳定、带宽与安全组好管，适合作为对外访问入口  
3. **办公室自建机也可以**，但通常更麻烦：运营商固定公网 IP 申请、路由器端口映射 / NAT、停电断网、机器自己要 7×24 在线——培训现场如实说「能做，运维成本更高」  
4. 权限、备份、谁能从外网登录——部署前单独定，本场不替 IT 拍板

现场收口：

> 「内网演示先跑通；要对同事开放外网，优先云主机 + 固定公网 IP + HTTPS。办公室机器不是不行，是固定 IP 和长期在线更难。」

### 4.5 和今天其它工具怎么串（30 秒）

```
WorkBuddy              →  日常交流互动、出草稿交货（专家/Skill 可直接用）
Grok Bot / EMS 内智能体 →  查、催、填草稿（经 API→MCP/工具门禁）
人确认                 →  关键信息落进 EMS（合同、台账索引、软著、审批等）
下一刀优先（未交付）   →  项目 / 采购 / 交付管理
```

## 五、能力总览（投屏用，1 分钟过）

```
WorkBuddy     →  先学会用：用途清单 · 四件套 · 专家/Skill · 交货
Grok Bot      →  主助手 + 专项助理；电脑持续 + 手机随身
微信机器人    →  手机发令，电脑执行，两边联动
EMS           →  合同/台账索引/软著/审批等逐渐一本账（AI 起草，人确认入库）
人负责        →  判断、合规、对客户承诺、最终提交
```

## 六、敏感信息红线（3 分钟，必须口头强调）

### 不要上传 / 不要乱贴公网或未授权渠道

- 客户现场拓扑全量、未脱敏点位表  
- 账号口令、密钥、令牌  
- 合同报价、未公开商务条款  
- 可识别到个人的隐私信息（证件号、手机号等，无必要勿贴）

### 可脱敏后使用

- 公开报错模式、通用流程、已公开文档结构  
- 去掉客户名 / 项目代号后的「问题类型」讨论

### 有疑问

先问直接主管 / 行政 / 项目负责人，**不默认「方便就贴」**。

## 七、收尾：一人一实验 + Q&A（8–10 分钟）

### 本周小实验（请同事自选至少 1 个；优先 A）

| 选项 | 本周小实验 | 成功标准 |
|------|------------|----------|
| A · WorkBuddy（优先） | 完成一件可交货的活（纪要表 / 周报 / PPT 骨架三选一）；可选：召唤一个相关大类专家 | 自己验收后真正发出或存档 |
| B · Grok Bot | 用主助手或一个专项助理跟完一件事（电脑或手机） | 能说清「我下了什么令、我改了哪三处」 |
| C · 微信一句（可选） | 若已开通：用一句完整指令完成催办或整理 | 回传结果可验收；未开通则改做 A 或 B |
| D · EMS 意识（可选） | 想一件「以后该进系统」的活（合同/台账索引/软著进度等） | 能说清：AI 草稿 → 人确认 → 进 EMS；不假装系统已全员可用 |

### 互动提问（备用）

1. 你工作里最烦的重复劳动是哪一件？打算用 WorkBuddy 怎么拆？  
2. 你更想先试「普通对话交货」，还是先试「召唤一个专家」？  
3. 你最担心哪一点：泄密、不准、还是流程没打通？  
4. （可选）如果公司要开外网 EMS，你更在意固定 IP / HTTPS，还是权限谁能登？

### 结束金句

> AI 不会自动让人变强；  
> **会下指令、会拆任务、会验收** 的人，会先变强。  
> 本周先把 WorkBuddy 用顺——比「全都想用」有效；  
> 能定稿的，再往 EMS 里收一笔。
