# 公安局静态大屏替换航信大屏

## 背景

航信现有大屏走组态运行时：登录后的监控入口按 `GET /GetSystemHomeDashboard` 跳到 `/AppRun/:uid`，由 `pageView` 拉起 `ISMRender`。`ISMRender` 继承 `ISMBase`，启动时用 `require.context` 扫入标准、图表、视频、电气、动环、3D 等两百多个组件，再整页加载 `display_model_layer`。页面上的测点在首屏批量请求实时值，之后由 WebSocket 持续推送。这套链路是航信大屏卡的代码原因。

公安局这边已经有一套可离线打开的静态大屏，技术栈和航信组态运行时分开。本次方案把它整份迁进航信，作为新的大屏页面。验收通过后，用它替换航信原来的大屏入口。替换之前两套页面只是为了对照，替换之后旧入口保留一个版本用于回退，不长期做两套主界面。

本机用一个新的 SQLite 文件提供数据：把现场 2026-10-23 的 MySQL 备份 `Mysql_Backup_2026-10-23_17-00-32.sql`（解压后约 584MB）转成 `ism_server_user/data/db/ism-hangxin-20261023.db`。不覆盖现有 `ism.db`，不导入本机 MySQL。正式环境数据已经就绪，实施只交程序文件，不带这个新库，不在现场恢复。上线后大屏读正式环境现有接口。历史仍走现有历史配置：配置为 TDengine 时查询超级表 `ISMHistoryDb.TempleteHistoryDatas`。公安局 `dcim-data.js` 不写入航信库。

本次只拷资料、写方案。不改业务代码，不建分支，不 commit，不打包，不发微信，不启服务。

建议实施分支名：`feature/hangxin-dashboard-from-gongan`。这次没有创建该分支。

航信端口：前端 `7080`，接口 `8081`（`ism-front-end-v2/vue.config.js` 把 `/api` 代理到 `http://127.0.0.1:8081/`，`ism_server_user/conf/app.conf` 的 `httpport=8081`）。桌面演示包手册里的 `8082` 是那份 Windows 演示包自己的接口端口，实施时不要拿来当航信后端。

## 公安局大屏是什么

这是零依赖静态页，没有 Vue、没有 webpack、没有 `node_modules`。`index.html` 只链本地 CSS 和 JS。舞台按 1920×1080 用 CSS `transform: scale` 缩放（`js/core.js` 的 `DESIGN_W` / `DESIGN_H`）。路由是 `location.hash`，例如 `#/dashboard`。页面注册在 `window.App`，同一时刻只挂一个页面，离开时调用 `unmount`。

图表在 `js/charts.js` 里自己画。空间是 `bld-svg.js`、`bld-iso.js` 和 `bld-3d.js`（自绘 Canvas，约 88KB），没有 Three.js 场景和 glTF 模型加载。

数据形状是 `window.DCIM`。`static-app/data/dcim-data.js` 文件头写明：项目名「北京公安局数据中心」；楼层、机房、告警、时序来自导出；资产台账 4293 条里只有 31 条真实种子，其余按分布合成。这份文件约 2.2MB，只适合当画面样例，不能写入航信库。

`static-app` 顶栏 9 项：空间巡检、设施监控、驾驶舱、容量总览、资产管理、工程配置、系统管理、报表报告、自监控。

`bjga-shell` 顶栏改为：驾驶舱、空间巡检、运行监控、配电专业、能效碳排、容量总览、资产管理、报表报告、运维中心、安全审计；「更多」里是数据治理、工程配置、自监控、系统管理。它的 `boot-data.js` 在打开时请求一次 `GET /api/bjga/bootstrap`，成功后把返回的 `dcim` 写进 `window.DCIM`。`power.js`、`energy.js`、`ops.js`、`audit.js`、`govern.js` 继续请求 `/api/bjga/...`。这些路径依赖另一套 `bjga_*` 数据，航信没有，也不新建。

驾驶舱里 PUE 仪表有一个 4000ms 的 `setInterval`，只在浏览器里轻微改动示意数字（`dashboard.js`）。`bjga-shell` 的系统管理文案写明：打开页面时请求一次 bootstrap；这段动画不改已经采到的功率；要看最新采集需重新进入页面。所以它比航信轻，是因为一次装入当前页、没有组态组件全量扫描，也没有按点位持续打接口。

## 航信现有大屏为什么卡

入口以代码为准：

| 入口 | 位置 | 行为 |
|---|---|---|
| `/dashboard` | `router.map.js` 的 `dashboard` | 项目管理页 `@/pages/project/dashboard` |
| `SCADAMonitor` | 同文件 | `createHomeDashboardRedirect()` |
| 默认大屏 | `src/config/homeDashboard.js` | 读 `GET /GetSystemHomeDashboard` 得到的 `dashboardUuid`，跳到 `/AppRun/${uuid}`。未配置则回 `/dashboard` |
| `/AppRun/:uid` | `router.map.js` | 组件 `@/pages/ISMDisPlay/pageView` |
| `/ISMDisPlay/DisPlayRunApp` | 同文件 | 旧地址，重定向到 `/AppRun/:uid` |
| `/DisPlay3DRunApp/:uid` | 同文件 | 三维预览，独立于默认大屏 |

`ISMRenderLoader.vue` 写明：`ISMRender` 含 `ISMBase` 和 200 多个子组件，必须单独成 chunk。`ISMBase.vue` 对 `ISMComponents/standard`、`charts`、`video`、`3d`、电气、动环、一次图等目录做 `require.context`。首屏还要 `getDisplayModelLayerData` 拉取 `display_model_layer`。`db.go` 里给这张大表补了 `idx_dml_model_deleted(model_id, deleted_at)`，注释说明大表迁移容易被这张表拖住。

实时值：`ISMRender.vue` 的 `InitPagerRealData` 把当前页绑定的测点 uuid 分批调用 `getRealDataByUuid`（`/api/getRealDataByUuid`）。之后 `App.vue` 连接 WebSocket（`/ws`，端口来自系统参数，`app.conf` 里 `wsport=10225`），`Cmd=="RealData"` 时经 EventBus `readDataPush` 推到各组件。`app.conf` 的 `realdatapushmergems=2000` 表示同设备同点位在合并窗内只保留最新值。`GetCurrentAlarmList`（`models/alarmModel.go`）在未传设备过滤时，对 `devices_alarm_list` 按 `clear_time < 2007-01-02` 查询，`Limit(1000000)`。组态页若整表拉取当前告警，会一次带回大量行。

三维：`ThreeModelEditor.vue` 接受 gltf、glb、obj、fbx、stl。它挂在三维编辑和 `/DisPlay3DRunApp`，默认的 `/AppRun` 只有图层里放了三维组件才会加载模型。

自定义报表的 luckysheet 在 `src/pages/reporting/diyReport/`，`ISMDisPlay` 运行时路径里没有 luckysheet。大屏卡的代码原因是组态组件全量、图层 JSON、首屏批量实时值和 WebSocket 推送；luckysheet 属于自定义报表，不算进这次大屏卡顿。

## 数据层：只读航信现有库和接口

不另建表。本机另建一个 SQLite 文件 `ism_server_user/data/db/ism-hangxin-20261023.db`，把现场备份转进去，表仍是下面这些已有表。适配层只查这些表。静态壳负责布局，适配层负责把航信字段填进 `window.DCIM`。公安局 `dcim-data.js` 和 `bjga_*` 不写入航信库。

GORM 使用单数表名（`db.go` 的 `NamingStrategy.SingularTable = true`）。`dbtype=1` 时 `db.go` 现在写死打开 `data/db/ism.db`。增加可选配置 `sqlitepath`，不填保持原文件；本机预览填 `data/db/ism-hangxin-20261023.db`。不改 `dbtype`，不覆盖 `ism.db`，不导入本机 MySQL。这个新文件不进 git，也不打进现场包。正式环境继续用自己的业务库。不碰寻智库。

`historyData.conf` 当前 `historyrecorddbtype=1`，历史页上的「内置」会读业务库里的 `devices_history_data_list`。历史页类型 `2` 是 TDengine，查询走 `GetDataTsHistoryList`，超级表为 `ISMHistoryDb.TempleteHistoryDatas`（`protocol/common/tdengine_time.go`）。航信历史以 TDengine 为准时，只把现有历史配置保持为类型 2，并调用下面已有历史接口。不新建历史库，不改历史备份目录，不调用 `HisDbBackUp` / `HisDbRestore`。

| 画面需要 | 已有表 | 已有接口 |
|---|---|---|
| 设备、机房、区域树 | `monitor_list`（`MonitorList`：名称、父子、`uuid`、`project_uuid`、在线 `Status`、经纬度） | `GET /monitortree` |

画面字段与航信字段的对应原则：

- 驾驶舱功率、温度、湿度、告警条数：从 `device_real_data` 和当前告警接口按测点名称或 uuid 绑定读取。PUE 若现场已在能源总览里配置测点，读 `/GetEnergyOverviewStats`；没有配置就显示空态，不用 `dashboard.js` 里的常数 1.50。
- 空间巡检的楼层和机柜：先用 `monitor_list` 的树。公安演示数据里的 407 机房、588 柜、42U 阵列是样例几何，只有航信项目里真实存在同名节点时才对上。对不上的柜位留空，不把 `dcim-data.js` 的合成资产插入 `monitor_list`。
- 资产管理台账：航信没有公安那套入库审批表。第一期大屏只展示 `monitor_list` 能表达的设备名称、在线状态和实时值。出入库、盘点、操作票仍留在静态壳的交互里，写操作先不做，避免为了写操作去建表。
- 历史趋势：当前页可见曲线调用 `/GetTrendChartData` 或 `/GetChartDataHistoryList`，时间窗默认短区间。配置为 TDengine 时这些接口内部进入 `GetDataTsHistoryList`。

适配脚本放在 `public/hx-dcim/js/hx-boot.js`，替换 `boot-data.js` 的 `/bjga/bootstrap`。它只发上面列出的请求。配电、能效、治理、审计页面里凡是调用 `/bjga/` 的按钮，在对照阶段改为只读已有接口或显示「航信暂无该专业台账」；不补 `/bjga` 路由。

实时值按需取。现有 WebSocket 按项目推 `RealData`（`pushToProjectConns`），没有按单点退订。新页维护「当前要看的测点」：进入配电室或列头柜时，立刻 `getRealDataByUuid` 取画面上的开关状态；鼠标放到某条支路时，立刻再取该支路全部测点，面板用这次返回的当前值。之后只更新名单里的点，其余推送丢掉。鼠标移开、换房间或离开页面就从名单拿掉。电容补偿柜不进名单。

## 替换步骤

1. 复制静态页到 `public/hx-dcim/`，先能离线打开驾驶舱和空间巡检的版式。
2. 接航信现有实时、告警、历史接口，按上表填 `window.DCIM`。演示用的 `dcim-data.js` 不参与运行。
3. 菜单进入 `/hx-dcim`，与原来的 `/AppRun/:uid` 并排对照：数字是否来自当前 `ProjectUuid`，旧组态页是否仍能打开。
4. 对照通过后，把默认大屏入口从 `createHomeDashboardRedirect` 指到 `/hx-dcim`。
5. 旧大屏保留：`/AppRun/:uid` 和 `display_model_layer` 原数据不动，菜单留「原组态大屏」一个版本，用于回退。

## 风险与保持不动的部分

- 密码链路保持原样：前端 MD5、`POST /login`、后端 bcrypt 比较 MD5 值。
- 历史备份保持原样：不调用、不改 `HisDbBackUp`、`HisDbRestore`、`data/hisdbbackup`。
- 自定义报表保持原样：不改 `diyReport` 和 luckysheet。
- `ISMBase` 组件注册、`ViewSvgText`、`ViewRealTable` 保持原样。
- `actions.js` 里的 `parseRawPageLayerFields`、`applyNavContextToPageConfig` 及其 import / export 保持原样。
- 实施只交程序文件。新 SQLite 只留在本机。不覆盖 `ism.db`，不改 `dbtype`，不在现场恢复备份，不碰寻智库，不对 TDengine 执行 `DROP`。正式环境数据保持原样。
- `bjga-shell` 里的 `/api/bjga/*` 不迁到航信路由。那些接口在别的演示包里对应独立表，航信用现有表读。
- 静态页的 4000ms 仪表动画只保留为视觉，绑定到航信实时值之后，示意随机数关掉，避免覆盖 `device_real_data`。
- 告警查询必须带过滤和较小的 `limit`。直接调用现有 `GetCurrentAlarmList` 且不传设备列表时，服务端上限是 100 万行。

## 验收

- 新大屏能打开：航信前端 `http://127.0.0.1:7080/#/hx-dcim`（或菜单「新大屏」），接口仍是 `127.0.0.1:8081`。驾驶舱、空间巡检、运行监控能切换，控制台没有脚本加载失败。
- 数据来自航信现有库：浏览器请求里出现 `/api/monitortree`、`/api/getRealDataByUuid` 或 WebSocket `RealData`、`/api/GetCurrentAlarmList`、历史接口 `/api/GetTrendChartData` 或 `/api/GetDataHistoryList`。不出现 `/api/bjga/`，库里不出现新的 `bjga_` 表。抽一条测点，画面数值与数据仓库里 `device_real_data.value` 一致。
- 旧功能不受影响：原 `/AppRun/:uid` 仍能打开；登录、自定义报表、历史备份页、组态编辑仍可用。`ISMBase`、`ViewSvgText`、`actions.js` 的上述两个函数无 diff。
- 性能看四项，并排记录旧大屏和新大屏：
  - 首屏：从进入路由到驾驶舱首帧的时间；旧大屏同时看 `ISMRender` chunk 体积和 `getDisplayModelLayerData` 耗时。
  - 首屏请求数和返回字节：新大屏应是静态资源加当前页测点的一批实时值，而不是整份图层 JSON 加全部组件。
  - 轮询与推送：新大屏打开后，除现有 WebSocket（合并窗 2000ms）外，不按秒轮询全量 `getRealData`。驾驶舱本地重绘间隔若保留，只重绘已有数值，默认与现有推送同频或更疏，不用 4000ms 随机数。
  - 内存：打开 5 分钟后的 JS 堆。旧大屏的对照样本是同一项目、同一 `ProjectUuid` 的 `/AppRun/:uid`。
