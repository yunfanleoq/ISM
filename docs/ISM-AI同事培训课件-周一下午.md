# AI 赋能工作坊：趋势 · 能力 · 价值

> **对象**：全体同事（研发 / 产品 / 项目 / 实施 / 行政）  
> **时长**：约 60–75 分钟（周一下午）  
> **形式**：讲解 + 场景演示 + 现场提问  
> **目标**：建立共同认知，明确「AI 能帮我们干什么」，并带走 1–2 个可立刻试用的做法

---

| 时段 | 模块 | 时长 | 要点 |
|------|------|------|------|
| 开场 | 为什么今天谈 AI | 5′ | 不是追热点，是提效工具 |

| 收尾 | 试用清单 + Q&A | 10–15′ | 每人带走一个小实验 |

## 开场（5 分钟）

### 今天不讲什么

- 不讲「AI 会不会取代人类」的空讨论  
- 不讲模型参数、论文细节  
- 不承诺「立刻上线一套企业级大系统」

### 今天要讲什么

1. **趋势**：行业走到哪一步了，和我们有什么关系  
2. **能力**：放到具体工作场景里，它到底能干什么、不能干什么  
3. **价值**：对每位同事日常工作的可感知收益（含报销等流程）

**一句话定调**：AI 是「副驾驶」，方向盘还在你手里；用得好 = 更快、更稳、更少重复劳动。

## 一、目前 AI 发展趋势（15 分钟）

### 1.1 三波演进（用业务语言说）

| 阶段 | 大致特征 | 对我们意味着什么 |
|------|----------|------------------|
| 感知与识别 | 图像识别、语音、OCR | 图纸/票据/现场照片可「读」 |
| 生成式（当下主战场） | 会写、会改、会总结、会对话 | 文档、代码、方案、邮件可加速 |
| Agent / 工作流（正在发生） | 不只聊天，还能按步骤帮你干活 | 报销、填表、查资料、串流程可半自动 |

### 1.2 2024–2026 企业侧可见趋势

1. **从「聊天玩具」→「工作入口」**  
   员工每天打开的不再只是搜索框，而是「帮我做完这件事」。

2. **从单次问答 → 多步任务**  
   例：读 Excel 点位表 → 生成设备清单 → 草拟联调检查项。

3. **从通用模型 → 场景 + 工具组合**  
   模型负责理解与生成；公司内部系统、表格、审批流负责「落地」。

4. **治理成为刚需**  
   敏感数据、客户项目资料、账号权限：能用，但要有边界。

### 1.3 对我们这类团队特别相关的方向

结合电力监控 / 组态 / 交付类业务：

- **工程交付文档加速**：方案、验收清单、操作说明草稿  
- **研发提效**：读代码、写测试、排查日志、补文档  
- **现场与运维辅助**：告警描述归纳、问题单初稿、手册检索  
- **内部流程减负**：报销、请假、会议纪要、周报

### 1.4 趋势小结（可投屏金句）

> 趋势不是「人人都会写 Prompt」，而是「重复脑力劳动会被工具吃掉」；  
> 竞争力来自：会提需求、会验收结果、会把 AI 接到真实流程里。

## 二、AI 的能力：场景具象化（25 分钟）

> 原则：每个能力都配「输入 → AI 做什么 → 你验收什么」。

### 2.1 软件开发场景

#### 场景 A｜读懂陌生模块（新人 / 跨模块协作）

| 步骤 | 内容 |
|------|------|
| 输入 | 一段函数 / 一个接口文件 / 一段报错日志 |
| AI 做 | 用白话解释职责、调用链、风险点；标出「建议先看哪几个文件」 |
| 你验收 | 对照真实代码，确认有没有幻觉；补上业务背景 |

**演示话术**：把「这个登录密码为什么总对不上」丢给 AI，让它按链路拆：前端 MD5 → 接口字段 → 后端 bcrypt。人负责确认是否符合项目约定。

#### 场景 B｜实现小功能 / 修小 bug

| 步骤 | 内容 |
|------|------|
| 输入 | 需求描述 + 相关文件片段 + 约束（不要改无关代码） |
| AI 做 | 给出改动方案、补丁草稿、边界条件 |
| 你验收 | Code Review：范围、回归风险、命名与风格 |

**价值**：把「从零空想」变成「审稿」；人从打字员变成主编。

#### 场景 C｜测试与文档

- 根据接口生成用例清单、异常路径  
- 把 PR / 提交说明整理成可读变更说明  
- 把运维手册从「散落在聊天记录」变成「可检索步骤」

#### 研发场景「能力边界」（必须讲清楚）

| AI 擅长 | AI 不擅长 / 需人把关 |
|---------|----------------------|
| 样板代码、重构建议、解释 | 客户现场真实拓扑与未文档化约定 |
| 日志归纳、复现步骤草稿 | 最终上线决策与责任 |
| 多文件线索搜索建议 | 保证「一次就对」——必须验证 |

---

### 2.2 流程管理 / 项目管理场景

#### 场景 D｜周报 / 项目状态汇总

| 输入 | 本周任务列表、问题单、会议要点 |
| AI | 按「进展 / 风险 / 下周计划」结构化输出 |
| 你 | 删掉不准的、补上客户敏感信息口径 |

#### 场景 E｜会议纪要 → 行动项

| 输入 | 录音转写或粗糙笔记 |
| AI | 提取决议、负责人、截止日期、待确认项 |
| 你 | 指定 Owner，发到群里闭环 |

#### 场景 F｜流程梳理与 SOP 初稿

例：「现场部署麒麟环境」——让 AI 先出检查清单骨架，实施同事用真实踩坑补洞。

#### 场景 G｜需求澄清助手

产品/售前把客户口述丢进去，让 AI 追问：范围、验收标准、例外、依赖。人决定哪些问题真要问客户。

---

### 2.3 与我们业务贴近的「具象例子」（可选加深）

1. **点位表 / Excel**：归纳设备类型、缺失列、命名不一致提示  
2. **告警文案**：把工程师口语转成客户可读说明  
3. **部署手册**：把聊天里的命令整理成「复制即用」步骤（仍需实测）  
4. **大屏/组态需求**：把「要科技感、要钻探」转成可评审的页面结构大纲  

> 强调：涉及客户数据、项目库、账号口令——**不要直接粘贴到公网工具**；走公司认可的渠道。

---

### 2.4 能力地图（一页总览，适合投屏）

```
理解  → 读文档 / 读代码 / 读表格 / 读票据
生成  → 文案 / 代码 / 清单 / 纪要 / 方案骨架
转化  → 口语→正式、长文→要点、表格→结构
协助流程 → 填单草稿、分类、提醒缺项、串联步骤
人负责  → 判断、合规、对客户承诺、最终点击「提交/发布」
```

## 三、AI 对员工的价值点（15 分钟）

### 3.1 价值分层（避免只讲「高大上」）

| 层级 | 例子 | 体感 |
|------|------|------|
| 每天都能用 | 写邮件、改周报、整理纪要 | 省 15–40 分钟/天 |
| 每周都能用 | 报销材料、方案初稿、测试清单 | 少一次加班式赶工 |
| 项目级 | 模块理解、问题排查辅助 | 缩短卡住时间 |

### 3.2 重点例子：自动化报销（具象化讲透）

**痛点还原**（共鸣开场）：

- 票找不全、科目选错、事由写不好、来回驳回  
- 「月底集中交」变成加班填表

**AI 能帮到的环节**（按流程拆）：

| 环节 | 人工现在怎么做 | AI 如何辅助 | 人仍要做什么 |
|------|----------------|-------------|--------------|
| 收票 | 拍照/PDF 堆在微信 | OCR 识别金额、日期、商家 | 核对真伪与是否可报 |
| 分类 | 凭经验选科目 | 建议科目与费用类型 | 按公司制度确认 |
| 填写 | 空白表硬写 | 生成事由说明、行程摘要 | 删改敏感/不实信息 |
| 自检 | 提交后才发现缺附件 | 提交前检查缺项清单 | 最终提交责任在人 |
| 问答 | 问行政「能不能报」 | 基于制度 FAQ 先答一轮 | 制度解释以行政为准 |

**演示脚本（现场可口述或投屏）**：

1. 出示一张餐饮发票信息（脱敏）  
2. 让 AI 输出：建议科目、事由草稿、附件检查项  
3. 指出哪里必须人工改（招待对象、是否超标、项目归属）

**预期收益话术**：不是「机器替你报」，是「第一次就填对概率变高、被退回次数变少」。

### 3.3 其他高共鸣价值点（按角色点名）

**研发**

- 卡壳时先问「可能原因 Top3」再打断同事  
- Code Review 前先让 AI 挑低级问题  
- 接口/配置变更自动生成说明草稿

**产品 / 项目**

- 需求从聊天记录提炼成可评审条目  
- 风险清单、验收标准模板化  

**实施 / 运维**

- 现场步骤检查表、常见故障问答草稿  
- 客户沟通邮件语气润色  

**行政 / 财务 / 全员**

- 报销、请假说明、会议安排、制度问答  
- 通知公告初稿  

### 3.4 「价值」落地的三个条件（避免听完就散）

1. **有边界**：什么能贴、什么不能贴（客户数据、密钥、未公开商务）  
2. **有验收**：AI 输出默认是草稿，提交前人要过一眼  
3. **有习惯**：选 1 个高频场景练两周（比「全都想用」有效）

## 收尾：试用清单 + Q&A（10–15 分钟）

### 本周「一人一实验」（可投屏，请同事自选）

| 角色 | 本周小实验 | 成功标准 |
|------|------------|----------|
| 研发 | 用 AI 解释一个陌生函数 + 自己验证 | 能讲给同事听且无硬伤 |
| 产品/项目 | 一次会议纪要 → 行动项表 | 群里发出去且有 Owner |
| 实施 | 一份部署/排查步骤整理成清单 | 同事按清单能走通 |
| 全员 | 一笔报销/请假说明用 AI 打草稿 | 一次通过或少一轮修改 |

### 互动提问（备用）

1. 你工作里最烦的重复劳动是哪一件？  
2. 你最担心 AI 的点是什么（泄密 / 不准 / 被替代）？  
3. 如果公司只先做一件自动化，你投哪票？（报销 / 周报 / 知识库问答 / 代码助手）

### 结束金句

> AI 不会自动让人变强；  
> **会提问、会拆任务、会验收** 的人，会先变强。

## 附录 A｜演讲者备注（不投屏）

- 时间紧就砍「2.3 业务加深」，保报销与研发两个主例子。  
- 现场若可联网，优先演示「纪要 → 行动项」或「发票信息 → 报销草稿」；代码演示准备离线截图兜底。  
- 遇到「会不会裁员」：强调组织要的是产出质量与速度，个人护城河是业务判断与责任闭环。  
- 遇到「我们工具还没采购」：先讲「个人合规范围内能做的」+「后续可统一选型」，避免变成采购吐槽会。
