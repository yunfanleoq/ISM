Opening

先定调

AI 是「副驾驶」，方向盘还在你手里。
用得好 = 更快、更稳、更少重复劳动。
  • 不讲空泛替代论，不讲论文参数
  • 不承诺「明天上线整套企业大系统」
  • 讲清楚：能干什么、不能干什么、人负责什么
Part 1 · 趋势

三波演进（业务语言）

感知与识别

图像 / 语音 / OCR
图纸、票据、现场照片可「读」

生成式（当下）

会写、会改、会总结、会对话
文档、代码、方案可加速

Agent / 工作流

不只聊天，还能按步骤干活
报销、填表、查资料可半自动

Part 1 · 趋势

企业侧看得见的变化

  • 聊天玩具 → 工作入口：目标从「问一句」变成「做完这件事」
  • 单次问答 → 多步任务：读表 → 清单 → 检查项
  • 通用模型 → 场景 + 工具：模型理解生成，系统负责落地
  • 治理成刚需：敏感数据、权限、客户资料要有边界
Part 1 · 小结

记住这一句

趋势不是「人人都会写 Prompt」，
而是「重复脑力劳动会被工具吃掉」。

竞争力 = 会提需求 · 会验收 · 会接到真实流程。
Part 2 · 能力

每个能力都按同一公式讲

输入→ AI 做什么→ 你验收什么

没有验收的「生成」，只是更快地制造错误。

Part 2 · 软件开发

场景 A：读懂陌生模块

输入函数 / 接口文件 / 报错日志
AI 做白话解释职责、调用链、风险；标出建议先看的文件
你验收对照真实代码，排除幻觉，补业务背景

例：登录密码对不上 → 拆前端 MD5 → 接口字段 → 后端比对链路

Part 2 · 软件开发

场景 B：小功能 / 小 bug

  • 输入：需求 + 相关片段 +「不要改无关代码」
  • AI：方案、补丁草稿、边界条件
  • 你：Review 范围、回归、风格

角色变化：从打字员 → 主编

边界
  • 擅长：样板、解释、日志归纳
  • 不擅长：未文档化现场约定
  • 上线决策与责任在人
Part 2 · 流程管理

流程 / 项目里怎么用

周报汇总

任务 + 问题 → 进展 / 风险 / 下周计划

会议纪要

笔记 → 决议、Owner、截止日期

SOP 初稿

部署 / 联调检查清单骨架，人补踩坑

需求澄清

口述 → 追问范围、验收、例外、依赖

Part 3 · 价值

对员工可感知的三层收益

层级例子体感
每天邮件、周报、纪要省 15–40 分钟
每周报销材料、方案初稿少一次赶工
项目级模块理解、排查辅助缩短卡住时间
Part 3 · 重点例子

自动化报销：不是替你报，是少被退回

环节AI 辅助人仍要做
收票OCR 金额/日期/商家核对真伪与可报性
分类建议科目按制度确认
填写事由、行程摘要草稿删改不实信息
自检缺附件清单最终提交责任
Part 3 · 分角色

你可能最先用到的点

Part 3 · 落地

价值落地的三个条件

有边界

什么能贴、什么不能贴

有验收

输出默认是草稿

有习惯

选 1 个高频场景练两周

合规提醒

敏感信息红线

不要上传
  • 客户现场全量拓扑
  • 未脱敏点位表
  • 账号口令 / 密钥
  • 合同报价等商务机密
可脱敏后使用
  • 公开报错模式
  • 通用流程步骤
  • 已公开文档结构
  • 疑问先问主管 / 行政
