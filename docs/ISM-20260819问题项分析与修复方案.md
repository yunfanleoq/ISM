## 双路径说明（问题 3，给现场）

- `native-bitunpack`：脚本能编译成纯 `BitGet + SetDeviceData` → 源点变化时拆位写目标
- `anko-onchange`：编译失败 → 解释执行，带 delay 周期跑

本轮不关掉 native，补齐周期 Settle 与手动执行日志，使两条路径都能写值并推告警。

## 明确不做

- 不改密码 MD5→bcrypt
- 不大改 ISMBase 组件注册、`actions.js` 导航解析
- 不批量改 100+ 组件的 `animateType`（本轮只修 ViewMenu）
- 不把备份上传做成静默还原

## 验收

1. 新增页面后可保存；运行态点击已绑定页面的菜单能跳转，不再空白崩溃
2. 历史库备份：有 taosdump（本机或 docker 容器）时可备份；无工具时 UI 明确提示
3. 定时 600s：一小时约 6 条（允许 ±1）；日志为汇总 `wrote/fromDB/reusedLast`，不再按点 `skip cycle`
4. 按位脚本：native 与 anko 均能更新目标点并推报警；手动执行有 `ExecSysScript` 日志
5. 虚拟设备全量导出含「报警触发值(0,1)」；改 Excel 再导入后库内值已更新
6. 备份上传成功后提示「不会自动覆盖业务库，请点还原」；打补丁不得覆盖 OceanBase / `ism.db`
