## 对照结果

### 1. 配电室 5A1 一次图（对照图2，图1只用来核对电容补偿不该出现）

设计稿要求：按 CAD 的上下级关系画手绘一次图。普通馈线红，UPS 进出线绿。要有 5A1-T1-401，悬停能看到这一回路的测点。电容补偿柜不画。

实测：左侧选中配电室 5A1。画面上有 5A1-T1-401，以及 411、412、413–416、445、T2-402、T2-421 至 T2-426、市电测试箱、U11–U14、U21–U24、母联、大旁路，下面有 5A1/5A2/5A3/5A4 的列头列尾分组。带测点的红线 56 条，键是 T1、T2 馈线，例如顶上横母线 `配电室5A1_T1_401` 从 x=375 到 x=1653。绿线 52 条，键是 U、X、Y 这些 UPS 进出线。全文没有「电容」或「补偿」。悬停 5A1-T1-401，标题就是这个回路，列出 A/B/C 相电流、线电压、相电压、频率、有功/无功/视在功率、电度、谐波、开关状态、故障状态、通讯状态，并且有实时数（例如 A 相电流 89.18 A）。

一致的部分：上下级、红馈线、绿 UPS、401 回路悬停、不画电容补偿柜。

有出入：y=659 有两条没有回路名的长横线（x=608–1492 和 x=1806–2690，各长 884）被画成绿色。绘图方法里普通母线应是红、UPS 才是绿。这两条没有测点名，不能算成某条 UPS 出线。另外整张图是按工程备份重排的，不是图2的像素级描摹，分组能对上，位置不会和手绘一格不差。

### 2. 机房模块 2A1 的 A 列头、B 列头（对照图3、图4）

设计稿要求：点不同列头，右侧主画面要换。A 列头按图3：进线和各支路开关，三相回路一个框里三把刀，307 这种没有 A/B/C 的单独一把。悬停 101A 要有该支路数据。白点、OUT、下箭头留在支路刀上。

实测：A 列头选中后，标题是「A列头进线」，101 到 108、201 到 208、301 到 306 都是三相，各有一个框和 A/B/C 三把刀。306 是一个框、三把绿刀，相位标在 306A/B/C。307 没有框，只有一把绿刀，宽度是单相的 108，不是三相的 252。点 B 列头后，选中项变成 B 列头，标题变成「B列头进线」，测点键变成 `B列头_主路`、`B列头_支路101A` 这一套，画面上不再有 A列头 的键。悬停 101A，标题是 101A，有支路电流、有功功率、有功电能、开关状态、电流越限告警。当时数值多为 0，开关状态为 1，和这三把刀显示红色合闸一致。支路刀有白点、OUT、下箭头。

一致的部分：A/B 切换会换主画面和测点；306 三相一框；307 单相单独一把；101A 悬停有支路数据。

有出入：

- 图3 画到 306，图4 局部多一把 307。实画面还多了 109、209、308、309，都是单相、没有框。308 就是上面那把绿色分闸刀。绘图方法写了按实际支路画，所以比静态图多回路说得通，但和这两张图的编号不是同一套。
- 图3 顶上写的是「2A1进线」，实画面写的是「A列头进线」「B列头进线」。
- A 列头 72 把刀，71 个 OUT 和下箭头。少的那一个是进线主开关，支路刀是齐的。
- A、B 两柜都是 33 把红刀、39 把绿刀。画面和测点键已经换成 B，红绿把数碰巧一样，不要理解成 B 没有重画。

### 3. 空间巡检

设计稿要求：按现有配电室、数据机房做成树，不是公安局楼层平面。

实测：顶栏「空间巡检」打开后，提示是「按航信监控树选择。点配电室开一次图，点机房开列头柜」。左侧是配电室 4 个（5A1、3A1、3A2、4B1）、机房模块 12 个（2A1 到 5A4）、数据机房 16 个（2B1 到 5B4）。正文写明「监控树没有楼层这一级」。没有北京公安局，也没有 4F/5F 楼层平面。

一致。页面里出现「楼层」两个字，只是在说明没有这一级。

图4 是旧组态编辑器里的工程树，列了 2A1 数据机房的 A 到 K 和列尾。新画面把 2A1 放在「机房模块」下，目前只有 A 到 J 十个列头，没有 K 和列尾。这是树的分法不同，不是把巡检做成了公安局楼层。

### 4. 进画面只取看得见的开关

设计稿要求：进一张画面只取这张图上的开关，不要订全站。

实测：进入 A 列头时，`getRealDataByUuid` 分两批请求 60 个和 12 个 uuid，合计 72，和画面上 72 把刀一致。现场名称索引 `hx-field-index.json` 有 628 台设备、172925 个点名，那是启动时用来对名字的静态表，进页没有按这个数量去取实时值。悬停再追加当前回路，例如 401 或 101A。

一致。全量名称表仍然会在打开新大屏时下载，但那不是进页订阅全站实时值。

### 5. 默认入口仍是旧 /AppRun

设计稿要求：不把新大屏做成系统默认入口。

实测：浏览器打开 `http://127.0.0.1:7080/#/`，地址落到 `#/login`，登录页标题是循安科技电力监控平台，不是 `/hx-dcim`。路由表里 `/` 重定向到 `/login`，`/hx-dcim` 是单独的「新大屏」。已登录会话里，系统首页配置是 `/AppRun/9d5689fa-0243-b1b7-24d2-12ca4cb102b0`，名称「寻智机房环境平面监视-xunzhi-jf」。

一致的部分：默认入口不是新大屏，形式仍是登录后的旧 `/AppRun/{uuid}`。

有出入：当前库绑定的那张首页，名字是寻智机房平面监视，不是航信旧一次图。本次按要求没有改 sqlitepath，也没有改首页配置。

## 主要出入

1. 刀片下端已从圆弧正中移到下部 1/3 分界（弧长约 66.7%，坐标 (39.51, 70.92)）。上端在圆心。屏幕上单把刀大约只有 19×55 像素，这一下移大概只有两个屏幕像素，不放大不容易看出来。

3. 2A1 的 A 列头比图3/图4 多了 109、209、308、309 四路单相；进线标题是「A列头进线」，不是「2A1进线」；进线主开关没有 OUT。

## 如何继续解开一次图

### 现状（本机 `ism-hangxin-20261023.db`）

| 来源 | 配电室一次图 |
|---|---|
| 架构树叶子 | 24 间（含 ECC1/ECC2 为单独节点时计在树内） |
| `display_model_layer` 已有页 | **4** 间：配电室 5A1、3A1、3A2、4B1 |
| `hx-scenes.json` 已解开 | 同上 4 间 + 列头柜 20 页（2A1 的 A–J 列头） |

其余 **20** 间配电室在架构树里会灰显「一次图未解开」，但仍可点「下钻 / 关联」进入同编码机房模块或数据机房列头。完整清单见 `docs/hx-scenes-pending-power.json`。

### 导出脚本

仓库新增 `scripts/hangxin_export_hx_scenes.py`，从组态表 `display_model_layer`（`components` / `layer` 为 base64 JSON）转为与 5A1 相同结构的 `hx-scenes.json` 页面，**不经过**旧 `pageView` / `ISMRender`。

```bash
# 查看 DB 与架构树覆盖
python3 scripts/hangxin_export_hx_scenes.py --list

# 写出待补配电室清单
python3 scripts/hangxin_export_hx_scenes.py --manifest docs/hx-scenes-pending-power.json

# 导出并合并到前端 data（默认合并，按 page_id 覆盖）
python3 scripts/hangxin_export_hx_scenes.py --export-power --export-columns

# 指定其它 SQLite / 输出路径
python3 scripts/hangxin_export_hx_scenes.py --db path/to/hangxin.db -o ism-front-end-v2/public/hx-dcim/data/hx-scenes.json --export-power
```

现场若还有 **制作画面文件.zip** 内 MySQL 全量库，导入/指向该库后重新执行 `--export-power`，有新 `配电室*` 页即可追加解开。模型 uuid 默认 `b620dc75-1da2-351b-b89e-05b5cb608886`（与现有 scenes 一致）。
