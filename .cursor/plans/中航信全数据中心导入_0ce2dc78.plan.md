# 中航信数据中心电力监控系统 — 全数据中心导入计划

## 复用策略（关键变化）
另一会话已沉淀技能 **`ism-auto-project-and-dashboard`**（[SKILL.md](.cursor/skills/ism-auto-project-and-dashboard/SKILL.md)），它把「建项目 + 画多层级钻探大屏 + 配首页 + 备份」做成了可复用流程，底座是
[import_hx_project.py](scripts/import_hx_project.py) + [build_ncc_dashboard.py](build_ncc_dashboard.py) + [homeDashboard.js](ism-front-end-v2/src/config/homeDashboard.js)。
**本次不重复造建项目/画大屏的轮子**，而是：① 把转发表数据喂成该技能要求的输入契约；② 适配它明确标注的"命名/层级空白点"；③ 补一个匹配真实 IP 的模拟器。

### 技能的输入契约（我们要产出的）
- `ism_data_models.json`：`devices[]`(name/templateType/aiStartAddr/diStartAddr) + `templates`/`models`
- `<项目>_complete_project_package.json`：`deviceModels[]` + `registerGroups[]` + `registerPoints[]`(muid+组+name+address+type)

## 背景与关键事实
- DB 为 **OceanBase**(`dbtype=4`, 端口 2881)，见 [app.conf](ism_server_user/conf/app.conf)；DB 读用 `pymysql`，写走后端 API(curl)。
- **新建独立项目**「中航信数据中心电力监控系统」，老项目 `航信机房` 保留不动。
- 三压缩包 = **三种 Excel 模式**(均已在样本中确认)：
  - `excel(1).zip`(30 xlsx, A 系列生产楼)：`模板`+主表+A20/A40/施耐德UPS/伊顿UPS，**与 1A 同构**。
  - `20260613.zip`(15 xls, B 系列机房模块)：`总结/两字节遥测/遥信/汇总`，列头柜模型(322AI/处理方式71)，设备名 `SJJF2A3_1A`。
  - `TB-配电室.zip`(11 xls, B 系列配电室)：`两字节遥测/遥信/Sheet1`，DX 型设备 `2A1_U2_DX17_1`。
- 三张汇总表(`汇总`→模块/`综合`→TB/`汇总表-excel`→A系列)给组态名→显示名→序号；`IP地址统计(1).xlsx` 给管理机 IP 全集。
- 规模：约 56 张转发表、约 1500~2500 台设备、数万点位。

## 模拟器替代真实采集（本次核心新增）
现场实时数据不可达 → 用**模拟器**提供实时值，且**IP 与现场匹配**。沿用 1A 既有思路并升级：
- 每个**管理机 IP** 用回环别名挂到本机：`sudo ifconfig lo0 alias 172.31.4.x`(及 172.20.255.x)。
- 扩展 [scripts/modbus_simulator.py](scripts/modbus_simulator.py)：监听各 IP:502，**每台设备一个唯一 slave id**，按其模型寄存器布局在模型基址(AI 1000/DI 8500 起)产出随类型/单位变化的实时值。
- 这样**绕开"每设备不同寄存器基址"难题**：设备靠 slave id 区分(与 [import_hx_project.py](scripts/import_hx_project.py) 现有 `extra.modbus.address=slave` 一致)，共享模型的 `register_start` 即模型基址即可，**无需改后端**。
- `extra_data` 填真实管理机 IP + 唯一 slave id；现场上线时把模拟器换成真实网关即可(届时再评估按 IP 单 slave + 寄存器偏移的改造)。

## 设备拓扑与命名适配（技能标注的空白点）
监控树：`项目根 → 楼栋(1A..5B/ECC) → 配电室/机房模块 → 列/机柜 → 设备`。新数据命名有三类：`*_S*`(A系列)、`SJJF*_*列`(模块)、`*_DX*`(配电室)。需改：
- [import_hx_project.py](scripts/import_hx_project.py)：`MODELS_DEF`/`RG_DEFS`(新增 列头柜/DX型/伊顿UPS 模型及独立寄存器组)、`get_cab_for_device()`(约 345)、`add_zone()` 树(约 338)、slave 分段(约 355)。
- [build_ncc_dashboard.py](build_ncc_dashboard.py)：`floor_key = name.split('_')[2]` 取段逻辑通用化。
- 前端 [ISMRunTreeNav.vue](ism-front-end-v2/src/pages/ISMDisPlay/ISMRunTreeNav.vue) 的 `floorKey()` 同步(uuid5 规则前后端必须逐字一致)。

## 双数据集
- **验证集**(先跑)：覆盖三种格式各一典型文件 —— `1B配电室`(A) + `2A3模块`(B模块) + `2A2配电室`(TB)，体量小、能验证解析/层级/模拟器/IP 全链路。
- **全量集**(后导)：全部 56 张转发表所有楼栋设备。
- 两套都产出独立的契约 JSON；脚本同一套，仅切换输入包路径与项目模式。

## 阶段实施
### 阶段 0：解压与格式归一
Python `zipfile`(cp437→gbk)解压到 `数据点位转发表/_unzipped/{A,模块,配电室}/`；`soffice --headless --convert-to xlsx` 批量转 `.xls`(已装 `/opt/homebrew/bin/soffice`)，过滤 `~$` 临时文件。

### 阶段 1：统一三格式解析器
`scripts/parse_forwarding_tables.py` 三适配器→统一中间结构(每文件 gateway{ip,backup_ip,port}、devices[{sn,显示名,model_type,ai_start,di_start,室,柜,楼栋}]、models{点位 name/offset/系数/parse_mode→Go type/unit/is_di/bit})。复用 [analyze_excel_v4.py](scripts/analyze_excel_v4.py) 的 parse_mode→Type 映射；用三张汇总表+IP统计交叉校验，出解析报告。

### 阶段 2：产出两份契约 JSON × 两套数据集
按技能契约生成 `ism_data_models.json` + `中航信_complete_project_package.json`，分别产【验证集】【全量集】。严守 SKILL 坑点：模型隔离、地址类型(#20)、`{val}*系数`、`type=1/deviceType=2`。

### 阶段 3：命名/层级与模型定义适配
见上"命名适配"。新增 列头柜/DX型/伊顿UPS 的 `MODELS_DEF`/`RG_DEFS`，registerCount=max(offset)+1。

### 阶段 4：模拟器(匹配 IP)
见上"模拟器"。先为验证集涉及的 3 个 IP 做回环别名+服务。

### 阶段 5：验证集端到端
按技能 S0~S10：`import_hx_project.py`(项目名=中航信数据中心电力监控系统,`--new`)→回查 UUID 填 `build_ncc_dashboard.py`→画大屏→改 `homeDashboard.js`→启模拟器→6 条 SQL 校验 + [_verify_ncc.py](scripts/_verify_ncc.py)→浏览器(admin/123456)验设备数/钻探不串页/实时值/无白屏。

### 阶段 6：全量导入
验证集通过后切全量集，同一套脚本导入全部楼栋，重画大屏(顶层只显聚合，适配数万点位)。

### 阶段 7：备份与终验
[backup_project.py](scripts/backup_project.py) 备份；6 条 SQL 校验全过；硬刷 `http://localhost:7080/#/AppRun/<MODEL_ID>` 终验。

## 验收标准
- 项目「中航信数据中心电力监控系统」独立存在，设备树覆盖全部楼栋/室/模块，设备数与转发表一致。
- 数据/模型/设备管理三处自动填充，中文点位名正确，6 条校验通过(无跨模型污染/地址冲突)。
- 模拟器按真实管理机 IP 提供实时值，设备详情与大屏实时绑点正确、可逐级钻探。
- 大屏显示名为「中航信数据中心电力监控系统」，登录后落地、可回后台。
