# 启动告警与实时缓存优化

## 设计原则

- 数据库中的 `device_real_data.value` 只作为页面冷启动快照，不再作为重启后告警边沿判断依据。
- 重启后的第一批现场采样才是新运行周期的真实基线；启动稳定窗口内不逐点通知。
- 稳定窗口结束时，仍持续处于告警态的点位各保留一条可处置告警记录，并合并为一次启动告警摘要通知；随后恢复现有实时边沿告警逻辑。
- 不再启动时复制全表三份键值；只缓存本次运行中实际采集到的启用设备数据，未命中时使用数据库快照。

## 实施步骤

1. **建立统一的启动告警协调器**
   - 在 [`ism_server_user/protocol/common/common.go`](ism_server_user/protocol/common/common.go) 增加线程安全的启动状态：点位首样本、最近样本、连续稳定次数、当前告警态和待恢复告警。
   - 复用现有 `StartupAlarmDelay` 作为稳定窗口，避免新增重复配置；首样本只建立基线，窗口内相同状态持续采样，窗口结束后仅释放仍处于告警态的点位。
   - 稳定窗口结束后立即清空临时基线结构，使额外内存仅存在于启动阶段。
   - 对值比较做类型规范化，避免 `1`/`1.0`、不同浮点格式造成假变化。

2. **让所有主要告警入口遵循同一策略**
   - 在 [`ism_server_user/task/alarm/dealWithAlarm.go`](ism_server_user/task/alarm/dealWithAlarm.go) 的中央告警队列入口接入协调器，覆盖 MQTT、阈值触发器和设备状态告警。
   - 在 [`ism_server_user/protocol/modbus/modbusPthread.go`](ism_server_user/protocol/modbus/modbusPthread.go) 的 `DealWithModbusAlarmData` 接入同一协调器，修复当前绕过 `StartupAlarmDelay` 的路径。
   - 检查并接入其他仍直接生成告警的 `DealWith*AlarmData` 协议路径；保持原告警入库、清除和 WebSocket 数据结构不变。
   - 启动窗口结束时，仍为告警态的点位按点位生成一条告警记录，通知层只发送一次摘要，避免再次形成消息风暴。

3. **取消全表三键内存预热**
   - 将 [`ism_server_user/task/SyncData/SyncDataToMem.go`](ism_server_user/task/SyncData/SyncDataToMem.go) 从“遍历整张 `device_real_data` 并写入三份键”改为轻量启动初始化，不再加载普通实时值。
   - 在 [`ism_server_user/task/enter.go`](ism_server_user/task/enter.go) 移除无意义的全表预热协程；HTTP 服务不再与 383MB 表扫描争抢 CPU、数据库连接和内存。
   - 删除告警对 `deviceUuid+pointUuid` 数据库旧值复合缓存的依赖；启动去重改由首样本协调器负责，运行期继续使用已有告警状态表。

4. **统一实时值缓存写入并保留兼容性**
   - 在 [`ism_server_user/protocol/common/common.go`](ism_server_user/protocol/common/common.go) 增加统一的 `StoreDeviceRealValue`/`LoadDeviceRealValue` helper，以点位 UUID 作为主键；名称键仅为仍依赖名称查询的脚本和旧接口按实际采集写入。
   - 优先替换 Modbus、MQTT、SNMP、手工写值和设备状态等热路径中的重复 `Store`，不改协议采集和 WebSocket 消息语义。
   - 不再维护全量复合键副本。稳态缓存由约“三条 Map 项/全表行”下降为最多“两条 Map 项/本次运行实际采集点”，禁用设备和从未访问点不占实时缓存。

5. **为缓存未命中补齐数据库回退**
   - 保持 [`ism_server_user/controllers/deviceLibraryCtl.go`](ism_server_user/controllers/deviceLibraryCtl.go) 的分页查询以数据库 `value` 为快照、内存命中再覆盖；确认 `getRealData` 和 `getRealDataByUuid` 在空缓存时仍返回值。
   - 为名称查询、绑定查询和 [`ism_server_user/task/ISMScript/func/deviceData.go`](ism_server_user/task/ISMScript/func/deviceData.go) 增加精确 DB fallback，禁止为了一个冷点重新扫描或加载整表。
   - 采集产生首个实时值后自动覆盖快照，此后读路径继续返回内存中的真值。

6. **修正数据库落盘与启动竞态**
   - 检查 [`ism_server_user/task/RealData/dealWithRealData.go`](ism_server_user/task/RealData/dealWithRealData.go)，确保 SQLite/MySQL/OceanBase 都以现有批量写队列为主，不再依赖对全量名称 Map 的长时间 `Range` 扫描。
   - 保证协议首批实时值不会被后台数据库旧快照反向覆盖。

7. **测试、观测与回退**
   - 为启动协调器增加表驱动测试：首样本正常、首样本告警后恢复、持续告警、启动后新告警、浮点格式差异、并发多协议重复事件。
   - 运行后端定向 `go test`，并以现有数据库验证：8081 可及时监听、登录正常、首批不产生告警风暴、稳定窗口后持续真实告警仅恢复一次、后续告警/清除正常。
   - 对比优化前后启动耗时、RSS 峰值、Map 项数和进程存活；目标是取消 383MB 全表扫描，实时缓存项减少至少三分之一，启动峰值 RSS 明显下降。
   - 保留短期配置回退开关，可恢复旧预热行为；验证稳定后再移除兼容开关。
